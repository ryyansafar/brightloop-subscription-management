## Changed
- `/invoices`: list with Draft / Outstanding / Overdue / Paid / Cancelled filters, search by number or customer, 20 per page. Overdue = confirmed and past due (same rule as the dashboard and `?overdue=1` in the API).
- `/invoices/[id]`: Odoo-style form view: status bar (Draft → Posted → Paid, Cancelled off-flow), Confirm / Record payment / Send / Print / Cancel. The buttons call Ryyan's routes (`/api/invoices/{id}/confirm|cancel|send`, `POST /api/payments`) and refresh; errors from the API show as toasts. Print uses the browser print dialog with a print stylesheet (only the invoice document prints).
- Record payment dialog: amount in rupees (sent as paise), method, date, note; client checks (> 0, not above the amount due, no future date) plus the server's own checks.
- `/payments`: list with method filter, search, total received.
- Tested in the browser on seeded data: confirm → part payment → full payment (auto PAID) → send; cancel with a confirmation dialog; Cancel is hidden once an invoice has payments. No horizontal scroll at 390px. `npm run build` passes.
- New in `@/components`: `formatDate`, `formatPeriod` (shows the last covered day, since periods end exclusively), `toDateInput`, `postJson` (client helper for the `{ ok, data | error }` API shape). @pankaj @roshan: use `postJson` for your form submits.
- `src/app/(app)/loading.tsx`: instant loading skeleton for every back-office page.
